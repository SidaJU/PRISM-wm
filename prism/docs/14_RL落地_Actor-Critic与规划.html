RL 落地：Actor-Critic 与模型内规划

PRISM-WM 笔记 14 · RL 是什么、在我们项目里长什么样、怎么运作、实测效果

一句话：我们实现了 model-based RL——用 Actor（策略）做动作、 Critic（价值）打分，在世界模型的想象里训练（不碰真实环境）， 奖励由 v5 的物体位置预测算出；并用 CEM 规划验证模型真的能用于决策 （物体从 22.72cm 推到距目标 0.40cm）。

1RL 是什么

RL（Reinforcement Learning，强化学习）= 让一个"策略"通过试错学会做决策： 看状态 → 做动作 → 环境给奖励 → 调整策略，目标是累积奖励最大。

要素通用含义我们项目里
状态 s当前情况世界模型状态 (h, z)（232 维）
动作 a能做什么末端位移 + 夹爪（4 维，范围 −1~1）
奖励 r做得好不好自己算：−‖预测物体位置 − 目标位置‖
策略 π该怎么动Actor 网络
环境做了会怎样我们的世界模型（不是真实 MuJoCo）

2在项目里长什么样：两个新网络

文件 prism/model/agent.py：

agent.py
├── Actor  (策略)  (h,z) 232维 -> 动作 4维     ← "司机"
└── Critic (价值)  (h,z) 232维 -> V（一个数）   ← "导航预估"

Actor（司机）—— 给定状态输出动作

29  def forward(self, hz):
30      """确定性均值（评估时用）。tanh 压到 [-1,1] 再乘 action_scale。"""
31      return torch.tanh(self.net(hz)) * self.action_scale

训练时不直接输出动作，而是输出一个分布再采样（这样才能探索、也算得出概率）：

39  mean = self.forward(hz)
40  std = self.log_std.exp().expand_as(mean)
41  dist = torch.distributions.Normal(mean, std)
42  raw = dist.rsample()                            # 重参数化采样
43  action = raw.clamp(-1.0, 1.0)                   # 环境动作范围 [-1,1]
44  log_prob = dist.log_prob(raw).sum(-1)           # 这个动作的对数概率
45  return action, log_prob

Critic（导航）—— 评估"这个状态接下来能拿多少分"

59  def forward(self, hz):
60      return self.net(hz).squeeze(-1)      # 输出一个标量 V

3核心循环图

Actor 出动作 → 世界模型模拟后果 → 算奖励 → Critic 评估 → 两者一起更新

4怎么运作（一次完整训练）

① 取真实数据 8 帧 --observe()--> 起点状态 (h, z)        【世界模型，冻结】

② 在「想象」里循环 H=10 步：
   ┌───────────────────────────────────────────────┐
   │ a_t  = actor.sample(hz)      策略出动作（带随机）  │
   │ (h,z) = RSSM 推演(a_t)       世界模型模拟后果      │
   │ obj  = object_pred(hz)       v5：想象的物体位置    │
   │ r_t  = -‖obj - goal‖         算奖励（越近越好）    │
   │ V_t  = critic(hz)            价值预估             │
   └───────────────────────────────────────────────┘

③ 合成 λ-return：这个状态「实际值多少」= 奖励 + 后续价值

④ 更新两个网络：
   critic: 让 V 更准（MSE）
   actor : 让「好动作」的概率变大

关键一步：actor 怎么更新（策略梯度）

160  adv = rets - vals.detach()                     # 优势 = 实际回报 - Critic 预期
161  loss_actor = -(log_probs * adv).mean()         # 策略梯度
162  loss_critic = F.mse_loss(vals, rets.detach())  # 价值回归
adv（优势）含义对动作的影响
> 0这步比预期好✅ 增大该动作的概率
< 0比预期差❌ 减小概率
Critic 为什么必要：没有它，actor 只知道"最后好不好"，不知道"哪一步的功劳"； 有了 critic，每一步都有即时评分——这就是 Actor-Critic 比纯策略梯度稳定的原因。

5奖励设计（v5 是 RL 的前提）

67  r_t = -torch.norm(obj_next - goal, dim=-1) * reward_scale

obj_next 来自 v5 的物体位置预测头，goal 是数据集里的 desired_goal。

关键依赖：没有 v5（物体位置预测头），RL 根本没法做—— 我们没有任何其它方式知道"箱子被推到哪了"（箱子在 64×64 画面里只有 1~2 像素，从图像读不出来）。 v5 → RL 是直接的依赖关系。

6为什么叫 model-based（我们的特别之处）

普通 RL：  策略 ──动作──> 真实环境 ──> 下一状态 + 奖励        （慢、贵）
我们    ：  策略 ──动作──> 【世界模型】──> 下一状态 + 奖励      （快、免费）

环境由 RSSM 扮演，全程不碰真实 MuJoCo，世界模型参数也不更新（只当模拟器）：

56  hz = torch.cat([h_t, z_t], dim=-1).detach()   # 状态 detach：梯度不穿过模型

这就是 Dreamer 风格——在"梦里"练策略，一次训练几分钟，零真实交互开销。

诊断证据：模型是好的

证据数值说明
动作敏感性不同动作推演终点差 59 cm模型对动作有响应 ✓
CEM 最优动作方向主导方向 y = −0.726与真实目标方向（y = −0.225）同向 ✓
RL 结果13 cm策略梯度没找到 CEM 能找到的解
结论：卡点在策略优化，不在世界模型。 策略梯度依赖模型在 OOD 区域的梯度方向，而模型 OOD 时梯度不可靠； 采样规划（CEM）不依赖梯度，因此更鲁棒。
