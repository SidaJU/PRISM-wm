# 笔记 02：卷积、拉平、全连接是什么（手算版）

> 本小点回答：**卷积到底是什么？它是 MLP 吗？拉平、全连接又是什么？**
> 所有数字都跑得出来（见文末脚本），可以自己手算验证。

---

## 0. 先直接答：卷积是 MLP 吗？

**不是。** 它们是两个不同的东西。

| 名称 | 是什么 |
|---|---|
| **全连接层**（fc / Linear） | 每个输出连到**所有**输入 |
| **MLP**（多层感知机） | 好几层全连接叠起来 |
| **卷积层**（Conv） | 一个小窗口在图上一格格滑，窗口里的数加权求和 |

我们的 Encoder **两种都用**：
- 前面 **4 层卷积**：负责"看懂画面"（保留位置信息）
- 最后 **1 层全连接**：负责"收尾压缩"成 256 个数字

---

## 1. 卷积：一个小窗口在图上滑

为了能手算，用一张 **4×4 的灰度图**（真实是 64×64 彩色，原理完全一样）：

```
1  2  3  1
0  5  6  1
1  7  8  1
0  1  1  0
```

准备一个 **卷积核（kernel）**，2×2，只有 4 个数字：

```
-1   1
-1   1
```

这个核的含义是"**左边减右边**"——左边暗、右边亮的地方会算出大正数，也就是在**找竖边**。

**滑动过程**：窗口从左上角开始，每次右移 1 格，到行尾就换下一行。

**窗口停在左上角时**，盖住的是：

```
1  2
0  5
```

计算方式：对应位置相乘，再全部加起来

```
1×(-1) + 2×1 + 0×(-1) + 5×1 = -1 + 2 + 0 + 5 = 6
```

把 **6** 写到输出的左上角。

滑完 9 个位置（2×2 的窗在 4×4 的图上只能停 3×3 个位置），完整输出：

```
  6    2   -7
 11    2  -12
  7    1   -8
```

> 左上角 `6` 和我们的手算一致 ✓（程序输出 `6.0`）

### 三个要点

1. **权重共享**：kernel 只有 4 个参数，却产出了 9 个数——同一组权重在整张图上复用。
2. **只看局部**：每个输出只看 2×2 的范围，不是整张图。
3. **权重是学出来的**：上面那个"找竖边"的核是我为了好懂手写的。
   真实训练时它会自己变成有用的样子（比如"找橙色方块的边缘"）。

### 通道数 = kernel 的个数

- 用 **32 个不同的 kernel** → 得到 32 张结果图 → **通道数就是 32**
- 真实第 1 层：输入 3 通道（RGB），32 个 kernel → 输出 `(32, 32, 32)`

### stride=2 就是下采样

窗口每次跳 2 格而不是 1 格 → 画面尺寸减半（64→32→16→8→4）。
这就是笔记 01 里那张"画面越来越小"的表。

### UE 类比

> 卷积 = **后处理材质里的卷积滤镜**（Sobel 边缘检测、高斯模糊都是这个）。
> 一个小核在整张纹理上扫一遍，全局共用同一组权重。
> 用 32 个不同的核 = 跑 32 个不同的滤镜，得出 32 张结果图。

## 2. 为什么用卷积，不用全连接

同样把 `(3, 64, 64)` 变成 `(32, 32, 32)`：

| 做法 | 参数量 |
|---|---|
| 卷积 `Conv2d(3, 32, k=4, s=2)` | **1,568** |
| 全连接 | **402,653,184**（4 亿） |

**相差 25 万倍。**

原因：全连接里，每个输出要连到全部 12288 个输入像素；
卷积只有 `4×4×3 = 48` 个权重，全图复用。

额外好处——**平移不变**：
方块在画面左边还是右边，同一个 kernel 都能认出来。
全连接做不到，它会记住"方块必须在这个像素位置"这种死知识。

---

## 3. 拉平（flatten）：只是排成一条直线

```
多维 (2,2,2) : [[[0, 1], [2, 3]], [[4, 5], [6, 7]]]
拉平后 (8,)  : [0, 1, 2, 3, 4, 5, 6, 7]
```

Encoder 里：第 4 层卷积输出是 `(256, 4, 4)` → 拉平 = 256×4×4 = **4096 个数字**。

**UE 类比**：把 2D 纹理按行展开成 1D 数组。丢掉了"行"的概念，只剩一串数。

---

## 4. 全连接（fc / Linear）：全员加权求和

规则：**每个输出 = 所有输入 × 各自权重，然后求和**。

手算一个小例子（权重 `w = [[1,0,-1], [0,1,1]]`，输入 `x = [2,3,4]`）：

```
输出[0] = 2×1 + 3×0 + 4×(-1) = -2
输出[1] = 2×0 + 3×1 + 4×1    =  7
```

程序输出 `[-2.0, 7.0]` ✓

Encoder 最后一步是 `Linear(4096, 256)`：
**4096 → 256**，参数量 = 4096×256 + 256 = **1,048,832**（约 100 万）。

这就是 MLP 用的层。MLP = 好几层 fc 叠起来；我们这里只用 1 层。

**UE 类比**：一个矩阵变换——把 4096 个特征"投票"成 256 个结论。
注意它**没有位置概念**了，所以只能放在卷积之后（位置信息已经被卷积提取完了）。

---

## 5. 完整旅程（真实数字串起来）

```
一帧 64×64×3  = 12288 个数字
  │
  ├─ Conv(3→32,  k4 s2)   → (32, 32, 32)     画面减半，通道 32
  ├─ Conv(32→64,  k4 s2)  → (64, 16, 16)
  ├─ Conv(64→128, k4 s2)  → (128, 8, 8)
  ├─ Conv(128→256,k4 s2)  → (256, 4, 4)      画面只剩 4×4
  │
  ├─ flatten              → 4096 个数字
  ├─ fc (Linear 4096→256) → 256 个数字        ← 这就是 emb
  │
  └─ 输出 emb (256,)
```

Encoder 总参数：**1,738,976**（约 174 万）

---

## 6. 参数都花在哪（真实统计）

| 层 | 权重形状 | 参数量 | 占比 |
|---|---|---|---|
| conv.0 | (32, 3, 4, 4) | 1,536 | 0.1% |
| conv.2 | (64, 32, 4, 4) | 32,768 | 1.9% |
| conv.4 | (128, 64, 4, 4) | 131,072 | 7.5% |
| conv.6 | (256, 128, 4, 4) | 524,288 | 30.1% |
| **fc** | (256, 4096) | 1,048,576 | **60.3%** |
| 合计 | | 1,738,976 | 100% |

**直觉**：越往后画面越小但通道越多，参数集中在上层；
最后那个 fc 一层就占了 **6 成**。

---

## 7. 三个记忆点

1. **卷积 = 小窗滑动 + 权重共享**（不是 MLP）；**全连接 = 每个输出连所有输入**
2. **通道数 = kernel 个数**；**stride=2 → 画面减半**
3. **拉平**只是排成一条线；**fc** 是全员加权求和
