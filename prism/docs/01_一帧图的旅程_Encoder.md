# 笔记 01：一帧图的旅程

> 系列目标：用例子把世界模型讲清楚。**一次只讲一小点。**
> 本小点回答问题：**那张 64×64 的图，第一步去了哪里？被怎么处理？**

---

## 一句话

**一帧 12288 个数字，被 Encoder 压缩成 256 个数字。**

这 256 个数字就是"这一帧的摘要"，后面所有的预测都在这 256 个数字上做，不再碰原始像素。

---

## 1. 先看清一帧是什么

数据里存的是 `images`，形状 `(100, 64, 64, 3)` —— 100 帧、每帧 64 宽 64 高、3 个颜色通道。

单独拿一帧出来：

```
64 × 64 × 3 = 12288 个数字（每个数字是 0~1 之间的浮点数）
```

**问题**：12288 个数字太多了。如果直接用它去预测下一帧，模型要同时处理 12288 个变量，
而且其中充满了无关细节（背景噪点、桌面上每一条纹理）。

---

## 2. Encoder 做的事：逐级"降分辨率、加信息密度"

用你熟悉的比喻：**就像生成 mipmap 金字塔**，每一级画面尺寸减半。
但和 mip 不同的是——**通道数在翻倍**。

实际跑出来的每一步（这些数字不是我编的，见文末的验证脚本）：

| 步骤 | 形状 | 画面尺寸 | 通道数 |
|---|---|---|---|
| 输入 | (1, 3, 64, 64) | **64** | 3 |
| 第 1 层卷积+ReLU | (1, 32, 32, 32) | 32 | 32 |
| 第 2 层卷积+ReLU | (1, 64, 16, 16) | 16 | 64 |
| 第 3 层卷积+ReLU | (1, 128, 8, 8) | 8 | 128 |
| 第 4 层卷积+ReLU | (1, 256, 4, 4) | 4 | 256 |
| 拉平 | (1, 4096) | — | — |
| 全连接 fc | **(1, 256)** | — | **256** |

> 注：代码里用的激活函数是 **ReLU**（`nn.ReLU()`），作用是把负数归零、引入非线性。
> （曾误记为 ELU，以 `prism/model/rssm.py` 第 26~29 行为准。）

**规律**：位置越来越少（64→4），但每个位置携带的信息越来越多（3→256）。

直觉理解：
> 不再逐像素记录"这里是什么颜色"，
> 而是用 256 个"高层特征"描述整张图——比如"有个橙色方块在中间偏左""机械臂举起来了"。

最后一步 `fc` 把 4096 压到 **256**，压缩比 **48 : 1**。

---

## 3. 这 256 个数字叫什么

代码里叫 `emb`（embedding，观测嵌入）。

**类比（UE 语言）**：
```
一帧画面  ──Encoder──>  一个含 256 个 float 的 struct
```
就像你把一个 Actor 的完整状态序列化成一个紧凑 struct——
信息还在，但形式变得方便后续计算。

用真实数据跑一遍，输出的头 8 个数字长这样（现在是**随机初始化**的值）：

```
[0.018, 0.004, -0.018, 0.008, -0.01, 0.0, 0.008, 0.002]
```

**关键点**：这 256 个数字不是 zip 那样的无损压缩，是**学出来的**。
训练过程中，loss 会逼它只保留"对预测未来有用"的信息。
训练好之后，其中某几个数字可能就对应"方块在画面里的 x 坐标"这种具体含义。

---

## 4. 代码在哪

| 内容 | 位置 |
|---|---|
| Encoder 定义 | `prism/model/rssm.py` 第 **20** 行 `class ObsEncoder` |
| 调用它的地方 | `prism/model/rssm.py` 第 **100** 行左右，`RSSM.forward` 里的 `self.encoder(flat)` |
| 一帧怎么读进来 | `prism/model/dataset.py` 第 **18** 行 `class L0Dataset` |

`forward` 里有个小细节：它把整段序列一次性编码，而不是逐帧：

```python
flat = images.reshape(T * B, *images.shape[2:])   # 把 T 帧 B 个样本摊平
emb  = self.encoder(flat).reshape(T, B, -1)       # 一次全编完再折回去
```

这样比循环逐帧快得多（GPU 喜欢大批次）。

## 这一小点的三个记忆点

1. 一帧 = **12288 个数字**（64×64×3）
2. Encoder 是 **4 层卷积**：画面 64→4，通道 3→256
3. 输出 **256 个数字**（`emb`）= 这一帧的学出来的摘要

---

**下一小点预告**：这 256 个数字出来之后，会进"动力学核心"（RSSM）。
它要结合**上一时刻的记忆**和**这一刻的动作**，去猜**下一帧的 256 个数字**是什么——
那才是"世界模型"真正的部分。
