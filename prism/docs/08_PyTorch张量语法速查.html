PyTorch 张量语法速查

PRISM-WM 笔记 08 · 切片 / unsqueeze / squeeze / permute / contiguous —— 都在我们的代码里出现过

0为什么需要这篇

RSSM 处理的是 5 维数据 (T, B, C, H, W)，而数据在磁盘上是 (T, H, W, C)， DataLoader 打包成 (B, T, C, H, W)——中间全靠这几个操作倒腾维度。

它们不改变数据内容，只改变“怎么看这些数字”（形状、顺序、内存排布）。

1切片 [2:] / [:2]：取一部分

语法 [start : stop : step]，start 包含、stop 不包含，省略就取到头/尾。

以 a = [10, 20, 30, 40, 50] 为例（高亮 = 取到的元素）
写法结果含义
a[2:][30, 40, 50]从索引 2 到末尾
a[:2][10, 20]开头到索引 2（不含）
a[1:4][20, 30, 40]索引 1、2、3
a[::2][10, 30, 50]每隔一个（步长 2）
a[:-1][10, 20, 30, 40]去掉最后一个
a[-2:][40, 50]最后两个

在项目里的用法

images.shape          # (32, 16, 3, 64, 64)  即 (T, B, C, H, W)
images.shape[2:]      # (3, 64, 64)            ← 掐掉前两个（T、B），留下通道+分辨率

images.reshape(T * B, *images.shape[2:])   # → (512, 3, 64, 64)
好处：不硬编码尺寸。换成 128×128 时 shape[2:] 自动变成 (3,128,128)，这行代码不用改。 （* 是解包，把 (3,64,64) 拆成三个独立参数传给 reshape）

2unsqueeze / squeeze：加 / 删一个维度

深度学习里最常见的需求：单张图要凑成“一批”才能喂给模型。

unsqueeze 加一个大小为 1 的维度；squeeze 删掉所有（或指定）大小为 1 的维度
操作输入输出用途
x.unsqueeze(0)(3, 64, 64)(1, 3, 64, 64)单张图 → 一批（第 0 维加 batch）
x.unsqueeze(1)(32, 3, 64, 64)(32, 1, 3, 64, 64)加序列维（MPC 里把 32 帧当 1 条序列）
x.squeeze()(1, 3, 64, 64)(3, 64, 64)去掉多余的 batch 维
x.squeeze(0)(1, 3, 64, 64)(3, 64, 64)只删第 0 维

在项目里的用法

# dataset 取出的单样本是 (32,3,64,64)，要变成模型要的 (32,1,3,64,64)
images = s['images'].unsqueeze(1)      # 在第 1 维加 B=1

# MPC 里把本体变成 (1,10) 才能送进 imagine
prop = torch.from_numpy(prop).float().unsqueeze(0)
注意：squeeze() 不带参数会删掉所有大小为 1 的维度——如果 batch 恰好是 1，会误删！ 需要精确控制时用 squeeze(dim)。

3permute：重排维度顺序

直接把维度的先后顺序换掉（和转置 transpose 类似，但可一次换多个轴）。

DataLoader 给的是 (B, T, ...)，RSSM 要 (T, B, ...) —— 用 permute(1, 0, 2, 3, 4) 把前两维对调

在项目里的用法（核心）

# train_rssm.py 的 to_seq_batch()
images  = batch['images'].to(device).permute(1, 0, 2, 3, 4).contiguous()
#        输入 (B, T, 3, 64, 64)
#        输出 (T, B, 3, 64, 64)
为什么要转成 T 在前？
因为主循环是 for t in range(T)：这样 images[t] 一次就拿到 所有 B 条序列在当前帧的画面（形状 (B,3,64,64)），既方便又高效。
如果保持 (B,T,...)，就得写 images[:, t]，且在内存上是跨步访问，更慢。

另一个常见用法：HWC → CHW

# 磁盘上是 (H, W, C)，PyTorch 要 (C, H, W)
x = torch.from_numpy(img).float().permute(2, 0, 1)   # (64,64,3) → (3,64,64)

4contiguous：让内存重新排布成连续

permute 只改“看法”（元数据），不动内存——导致逻辑上相邻的元素在内存里是跳着放的。

permute 后逻辑视图变了但内存没动；contiguous 会真的拷贝一份按新顺序排好
permute 后.contiguous() 后
内存没变（还是原顺序）重新排布（拷贝一份）
访问跳跃访问（慢）连续访问（快）
能否 reshape/view❌ 常报错✅ 可以
经典报错： RuntimeError: view size is not compatible with input tensor's ... call .contiguous() before .view()
原因就是 permute/transpose 后内存不连续，而 view() 要求连续——补一个 .contiguous() 即可。 （reshape() 比较智能，内部会自动拷贝，但显式写 contiguous 更清楚）
代价：contiguous() 会拷贝数据（费时费内存）。 所以只在需要时调用（比如 permute 之后紧接着 reshape / view）。

5项目里的“组合拳”：数据怎么变形的

从磁盘到模型输入的完整变形过程
阶段形状用的操作
磁盘 npz(100, 64, 64, 3)—（HWC）
Dataset 取样本(32, 3, 64, 64)permute(0,3,1,2) + 切片 [s:s+32]
DataLoader 打包(B, 32, 3, 64, 64)自动 stack
to_seq_batch(32, B, 3, 64, 64)permute(1,0,2,3,4).contiguous()
Encoder 前(32×B, 3, 64, 64)reshape(T*B, *shape[2:])
Encoder 后(32, B, 256)reshape(T, B, -1)

6速查表

操作作用是否拷贝数据
a[2:]取切片否（视图）
unsqueeze(dim)加一个大小为 1 的维度否
squeeze(dim)删大小为 1 的维度否
permute(...)重排维度顺序否（只改元数据）
contiguous()让内存连续是（必要时才用）
reshape(...)改形状（自动处理连续性）必要时
view(...)改形状（要求连续）否
