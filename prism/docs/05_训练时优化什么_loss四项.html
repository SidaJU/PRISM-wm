0一句话

训练就是一件事：让四个误差都变小。它们加起来就是总 loss， 梯度下降沿着它去更新所有参数。

total = recon_weight × 重建
      + emb_weight    × emb 预测
      + proprio_weight× 本体预测
      + kl_weight     × KL
这四个误差，正好对应笔记 04 里那三条路的尽头 （②③ → 重建 / emb / 本体，prior vs posterior → KL）。 前面讲的所有结构，到这里才有了"训练目标"。

1四项总览

四项各自算一个误差，加权求和得到总 loss
项拿什么和什么比形状实测值（未训练）
重建Decoder 出的图 vs 真实图像(32,1,3,64,64)0.043130
embemb_pred vs emb（Encoder 摘要）(32,1,256)0.058420
本体proprio_pred vs 真实本体(32,1,10)0.338434
KLprior 分布 vs posterior 分布(32,1)0.238377
合计——0.678362

四项用的都是 MSE（均方误差）， 也就是"差的平方取平均"——除了 KL，它有专门的公式（下面讲）。

2逐项拆解

① 重建 loss：逼模型把画面还原出来

recon = torch.mean((out['recon'] - images) ** 2)

Decoder 把 emb_pred 还原成图，和真实输入图像逐像素比。

这一项最重要：它是唯一直接训练 Encoder 的信号。 模型能不能看懂画面，全靠它。

② emb loss：在"摘要空间"里比

emb_mse = torch.mean((out['emb_pred'] - out['emb'].detach()) ** 2)

不和像素比，而是和 Encoder 算出的 256 维摘要比 —— 相当于在语义层面比。

两层监督配合（像素 + 摘要），逼着 32 维的 z 真的留住关键信息。

③ 本体 loss：猜机械臂自己的状态

proprio_mse = torch.mean((out['proprio_pred'] - proprio) ** 2)

低维、精确、和动作强相关，给训练一个稳定的辅助信号。

④ KL loss：逼 prior 追上 posterior

kl = 0.5 * (lv_p - lv_q + (lv_q.exp() + (mu_q - mu_p)**2) / lv_p.exp().clamp(min=1e-4) - 1)
kl = torch.mean(kl)

这是两个高斯分布之间差距的解析公式（不用采样估算）。 它衡量的就是笔记 04 讲的那件事：prior 和 posterior 差多远。

公式里每个符号是什么

符号是谁出的含义维度
mu_pprior 网络闭卷猜的中心(B, 32)
lv_pprior 网络闭卷猜的不确定度（log 方差）(B, 32)
mu_qposterior 网络开卷判断的中心(B, 32)
lv_qposterior 网络开卷判断的不确定度(B, 32)

下标 p = prior（闭卷）、q = posterior（开卷）。lv.exp() = 真正的方差。

mu 和 z 不是一回事（容易混）：
mu = 分布的中心（靶心）；std = 宽度（抖动范围）； z = 从这个分布里采样出的一个值（实际射中的位置）：
z = mu + std × 随机噪声
训练时 z 取自 posterior（用 mu_q），想象时取自 prior（用 mu_p）。

公式在测什么：拆成两块

公式片段测的是什么
(mu_q - mu_p)**2位置差：两个分布的中心差多远
lv_p - lv_q（即 log 方差比）宽度差：一个比另一个"散"多少
/ lv_p.exp()用 prior 的宽度做归一（以闭卷为基准衡量开卷）
- 1 和 0.5 *数学常数：保证两个分布完全相同时 KL = 0

手算一个 2 维的例子（脚本 demo_05b_kl.py 可验证）

符号维 0维 1
mu_p（闭卷中心）1.0−0.5
mu_q（开卷中心）1.2−0.3
lv_p → 方差−2.0 → 0.13530.0 → 1.0
lv_q → 方差−1.5 → 0.22310.2 → 1.2214

以维 0 为例，代入公式：

0.5 × [ (−2.0−(−1.5)) + (0.2231 + (1.2−1.0)²) / 0.1353 − 1 ]
  = 0.5 × [ −0.5 + 1.9443 − 1 ]
  = 0.5 × 0.4443 = 0.2221

维 1 同样算出 0.0307，两维相加 = 0.2528。

验证：从 posterior 采 20 万个点、用 log q − log p 的平均来近似 KL， 得 0.2505 ≈ 0.2528 ✓ —— 公式没写错。 （也和 torch.distributions.kl_divergence 官方实现完全一致）

先回顾这两个分布（详见笔记 04）：

输入含义类比
posterior qh + 当前图像 emb看了图，判断准开卷考试
prior p只有 h只凭记忆，一开始差闭卷考试

KL(q ‖ p) 的作用：逼 prior（闭卷）去模仿 posterior（开卷）。

也就是训练会强迫「只凭记忆的猜测」尽量接近「看过真相后的判断」。 这样一来，记忆就被训练成能自己补全看不见的信息——这正是遮挡场景需要的能力。

为什么非有它不可：
想象（做梦）时没有图像，只能用 prior。
如果训练时不逼 prior 学好，那模型根本没法想象 —— KL 就是"想象力"的来源。

prior / posterior 的结构对比、训练时怎么协作， 见笔记 04「源」一节。

3一个关键细节：为什么写 .detach()

emb loss 那行有个 out['emb'].detach()，看起来不起眼，作用很大。

写法MSE 数值梯度会不会流回 Encoder
(emb_pred - emb.detach())0.058420不会
(emb_pred - emb)0.058420会

数值完全一样，区别只在梯度方向。

如果不 detach：预测头会为了"让误差变小"， 去改 Encoder 的输出（把摘要压成容易预测的样子）—— 这会让学到的表征退化（表征坍塌）。
加 detach 后：Encoder 只由重建 loss 训练，预测头只能自己追。

4权重与 free_bits

四个权重

参数默认值控制哪一项
recon_weight1.0重建（像素）
emb_weight1.0emb 预测（摘要）
proprio_weight1.0本体预测
kl_weight1.0KL

调它们就是调"更看重哪一面"。比如想让画面更清晰，就加大 recon_weight。

free_bits：防止 KL 塌成 0

if free_bits > 0:
    kl = torch.clamp(kl, min=free_bits)

如果不设下限，模型可能发现"干脆不用 z"最省事 —— KL 会降到接近 0， 潜变量就白学了（这叫 posterior collapse）。

free_bitsclamp 后 KL 均值
0.00.2384
0.10.2384（还没到下限）
0.50.5000（被顶到下限）

KL 原始范围：0.1414 ~ 0.3840，均值 0.2384。

free_bits 是怎么「修复」塌缩的：关键是梯度

塌缩是一个稳定的陷阱：模型发现「不用 z」总 loss 最低； 想重新用 z 就得让 KL 涨回来，而 KL 一涨 loss 就被惩罚。
—— 压小 KL 永远有奖励，用回 z 只有惩罚，所以塌了就再也回不来。

clamp 改掉了这个激励结构：

KL 的位置loss 里的 KL 项梯度
KL > free_bits正常有（鼓励压小 KL）
KL ≤ free_bits恒等于 free_bits（常数）0 —— 压小 KL 没有任何收益
也就是说：从 0 爬到 free_bits 这段，KL 是免费的 —— 这就是名字 free bits（免费的比特）的由来：每个维度的 z 前 0.1 nat 信息不收税。

数字例子（用我们的实测）：

无 free_bits有 free_bits = 0.1
塌缩时的 KL 项≈ 0clamp 后 = 0.1
想重新用 zKL 涨回 0.1 → loss +0.1 惩罚爬升段 KL 项恒为 0.1，零代价
结果塌缩稳如泰山用 z 只要能降重建 loss，总 loss 就降 → 被引导回「用 z」
诚实的边界：free_bits 只保证「z 被使用」（KL 不塌到 0）， 不保证 z 学到的信息有用（比如和遮挡相关）。
完整修复还要配合加强数据随机化——让"光靠记忆 h"不够用，z 才有活干。

KL 多小才算训练好？—— 不是越小越好

KL 很小，可能是含义好坏
prior 学会了从记忆预测 posterior，且 posterior 携带图像信息闭卷能力追上开卷✅ 成功
posterior 自己也没信息（z 死了），prior 天然等于它两者都是空壳❌ 塌缩
我们 20 epoch 实测属于坏的那种：KL 塌到 0.000002， z 里几乎没有信息 —— 因为确定性仿真光靠 h（记忆）就能预测一切，z 被绕过了。
正确的目标：KL 别太大（prior 跟得上），也别太小（z 有信息量）。
判断办法：遮挡画面时，z 还能不能帮忙补信息。

5实测：遮住画面后各项怎么变

把第 10~19 帧涂黑，看四项 loss 的反应：

项正常遮挡后变化
重建0.0431300.116993↑ 明显变差
emb0.0584200.053117略降
本体0.3384340.336074几乎不变

重建 loss 反应最大是合理的：它是唯一直接比像素的一项， 画面被涂黑它立刻就受不了。
而本体 loss 几乎不变 —— 因为机械臂自己的状态不受画面影响（这正好说明路③是独立的监督信号）。

6三个记忆点

  • 四项 loss：重建（像素）/ emb（摘要）/ 本体 / KL（分布差距），加权求和
  • emb loss 里的 .detach() 让 Encoder 只由重建 loss 训练，防止表征坍塌
  • KL 是"想象力"的来源：没有它，prior 学不会，模型就没法做梦

7out 与 rssm_loss：精确理解（含勘误）

常见理解（这一部分是对的）

  • 每个 batch 调用一次 rssm_loss
  • 它吃的是整个 batch 的结果（32 步 × 16 条 = 512 个时间步）
  • 每类误差各自求 mean → 得到 5 个量的字典（loss / recon / emb / proprio / kl）
  • 各项含义：
    • loss = 四项的加权求和
    • recon = 每一步重建图 vs 真实图的 MSE
    • emb = 每一步预测摘要 vs 真实摘要的 MSE
    • proprio = 每一步预测本体 vs 真实本体的 MSE
    • kl = 每一步 posterior vs prior 的 KL

需要修正的三处

常见说法修正
“out 里记录了每一步的中间量 z、h” out 里没有 h 和 z。它们在循环里算过，但没导出 （forward 只返回 emb / emb_pred / proprio_pred / kl / recon）。 这也是 state 参数“能进不能出”的原因。
“out 里还有四项 loss” out 里只有 kl 是 loss 分量；out 装的是预测产物 （emb_pred / proprio_pred / recon）。真正的 recon / emb / proprio 三项 loss 是在 rssm_loss 里拿 out 和真实数据现算的。
“每一步的参数” 模型参数（385 万）只有一份、共享，不随时间步变化，也不存进 out。 out 里存的是每步的激活值（预测结果），不是参数。

精确版：out 里到底有什么

键形状是什么
emb(32, 16, 256)Encoder 对真实图的摘要
emb_pred(32, 16, 256)模型预测的摘要
proprio_pred(32, 16, 10)预测的本体
kl(32, 16)每步 KL（已对 32 维求和）
recon(32, 16, 3, 64, 64)解码出的重建图

rssm_loss 里怎么算

recon    = torch.mean((out['recon'] - images) ** 2)                    # 现算
emb_mse  = torch.mean((out['emb_pred'] - out['emb'].detach()) ** 2)     # 现算（注意 detach）
proprio   = torch.mean((out['proprio_pred'] - proprio) ** 2)            # 现算
kl       = torch.mean(out['kl'])                                        # 只做 mean
total = recon + emb + proprio + kl      （各自乘权重后求和 → loss）
规模：512 个时间步 × 4 类误差 → 每类各自 mean → 4 个标量， 再加上加权和 loss = 字典共 5 个量。
一个容易漏的细节：emb 那项用了 .detach()—— 把真实摘要从计算图断开，梯度只更新 obs_pred，不回传 Encoder（防止表征坍塌，见第 3 节）。
