v5：物体位置预测头

PRISM-WM 笔记 12 · 为什么做、逐行代码、新流程图与实测结果

一句话：给 RSSM 加一个从隐状态 (h,z) 回归物体 xyz 的预测头，并纳入 loss。 结果：闭眼推演的末端误差 21.0cm → 6.8cm（降 67%），并首次优于"假设世界不动"（2.60× → 0.73×）； 物体位置第一次可评测（7.73cm，优于静止基线 11.43cm，方向正确）。

1为什么要做（背景与问题）

① 当时的困境：想象不如"认为世界不动"

指标（20 步想象）v2（无位置头）静止基线结论
末端位置误差21.01 cm8.07 cm❌ 差 2.60 倍
物体位置误差模型不输出物体位置 → 无法评测❌
模型能"画出世界长什么样"，但预测不了世界会怎么变——而且比"什么都不做（认为静止）"还差。 这意味着想象结果不能直接用于决策。

② 三个依据（为什么加位置头能解决）

依据说明
a. z 是画面信息的唯一入口obs_pred 只吃 (h,z)，吃不到 emb（笔记 11）。 所以只要逼 z 装载"物体在哪"，画面信息就真的进入了预测通路
b. 训练缺"难而重要"的梯度emb/proprio 早期就饱和到 1e-5（不再提供梯度）， KL 占 loss 95% 且被地板夹住（梯度 0）→ 后期训练几乎停摆。需要一个持续有梯度的目标
c. 仿真里物体真值免费可得gt/object_state[:, 0:3] 已有（743 局全都有）， 这是仿真相对真机的优势（privileged information）
关键澄清：把物体真值当预测目标（监督），不是当模型输入—— 与"obs/ gt 物理分离防泄漏"的设计不冲突。模型依然看不到真值，只能从图像里推断。

② prism/model/rssm.py — rssm_loss

第 199–202 行（函数签名）

def rssm_loss(out, images, proprio, kl_weight=1.0, emb_weight=1.0,
              recon_weight=1.0, proprio_weight=1.0, free_bits=0.0,
              object_pos=None, object_weight=1.0):
    """object_pos: (T,B,3) 物体位置真值（监督目标，不是模型输入）。
    给了它就会多一项 object_mse —— 这是 v5 逼 z 装载物体信息的关键。"""

用默认 None 保持向后兼容：不传就不算这项（旧代码/评测脚本不受影响）。

第 208–210 行（计算误差）

# v5：物体位置预测误差（单位：米²；典型值 1e-4 量级）
object_mse = (torch.mean((out['object_pred'] - object_pos) ** 2)
              if object_pos is not None else torch.zeros((), device=images.device))

就是 MSE：(预测xyz − 真实xyz)² 对所有时间步、所有序列、3 个坐标求平均。 单位是米²（实测 ep1 是 0.0345 → ep20 降到 0.0008，开方约 3cm 误差）。

第 219 / 223 行（进 total 与返回）

total = (recon_weight * recon + emb_weight * emb_mse
         + proprio_weight * proprio_mse + kl_weight * kl
         + object_weight * object_mse)
return {
    'loss': total, 'recon': ..., 'emb': ..., 'proprio': ..., 'kl': ...,
    'object': object_mse.detach(),
}

加进总 loss（参与反向传播），并作为独立一项返回（训练日志会打印 object=...）。

5为什么有效 + 一个诚实的观察

机理：物体位置头给了 (h,z) 一个直接且正确的监督目标。 即使 z 的信息量没暴涨，下游预测也被"锚定"在真实位置上，逐步漂移被持续纠正—— 这比单纯期待 KL 变大要可靠得多。
诚实观察：真实 KL 只从 0.020 涨到 0.026（+30%，不是暴涨）， 但误差从 21cm 降到 6.8cm。说明改善的主因是位置监督本身，而不是"KL 变大"。 （也说明之前寄望于"调 free_bits 让 KL 涨"的思路是错的——见笔记 11。）

后续可做的优化

  • 加大 object_weight（如 5.0 / 10.0）——进一步压低位置误差
  • 数据侧：更大的物体运动 + 更强的随机化（当前真实位移仅 7cm 左右，信号仍偏弱）
  • MPC 代价函数改用预测的物体位置（不再用"末端到目标"的间接代理）——可能让 MPC 第一次真正有效
