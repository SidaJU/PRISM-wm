0一句话

RSSM 每帧只做两件事：更新记忆 h，以及对"世界现在是什么样"给出判断 z。

前面 01~03 讲的 Encoder 只是把一帧变成 256 个数字（emb）。 RSSM 才是"世界模型"本身——它负责把这些数字在时间上串起来。

衔衔接：emb 出来之后去哪

先纠正一个印象：emb 不是一个，是一串

01~03 讲的是「一帧怎么变成 256 个数字」。但训练时喂进去的是一段序列（32 帧）， 所以 Encoder 会跑 32 次，得到 32 个 256 维向量：

写法含义
emb[0]第 0 帧的摘要（256 个数）
emb[1]第 1 帧的摘要
……
emb[31]第 31 帧的摘要

整段堆起来就是 emb，形状 (32, 1, 256) = （时间, batch, 维度）。

emb 有两个角色（这是衔接的关键）

角色去哪干什么
A. 修正记忆和 h 一起进 posterior把"当前看到了什么"注入，得到这一帧的判断 z
B. 当老师作为 emb_pred 的目标模型猜的摘要要逼近它 —— 这就是监督信号（下一小点讲 loss）

两个去处，一张图看清

emb[t] 只有两条出路：向右上进 posterior、向右下当比较目标。它不向左（不进 GRU）

逐个维度的走法（第 t 帧）

步骤操作维度变化
①取出 emb[t]256
②和 h[t] 拼起来进 posterior200 + 256 = 456
③posterior 输出均值和方差，采样出 z[t]456 → 64 → 32
④(h[t], z[t]) 进 obs_pred，猜出 emb_pred[t]232 → 256
⑤拿 emb_pred[t] 和 emb[t] 比一比算出 loss
⑥顺带把 emb_pred[t] 送进 Decoder 还原成图256 → (3,64,64)

别扭的地方：emb 既是输入又是答案？

你可能会觉得这是作弊——先把它塞进 posterior，再要求还原出它。关键在于中间有个窄门：

emb 是 256 维，而 z 只有 32 维。
信息必须先挤过 32 维的窄门，再被还原成 256 维 —— 模型被迫学会「什么才是真正重要的」。
这就像 JPEG：原图进去，压缩再解压，要求还原得尽量像。瓶颈逼着它丢掉无关细节。

但真正的"预测"能力不来自这条重建路径，而来自 prior：

场景z 从哪来emb_pred 的性质
训练时posterior（看了图）重建当前帧（练表征）
想象时prior（不看图）预测未来帧（这才是世界模型）

而 KL 那一项的作用，就是逼 prior 尽量接近 posterior —— 于是"不看图"的时候也能猜得八九不离十。

最容易搞错的一点：emb 不进 GRU。
时间上是错开的：第 t 步的 GRU 吃的是 z[t-1]（上一帧的判断）， 而 emb[t]（当前帧）只进 posterior。
所以图像信息是通过 z 间接影响记忆的，不是直接灌进去的。

时间展开图：连续三步怎么串起来

每个时间步：图 → emb →（和 h 一起）posterior → z；z 再传给下一帧的 GRU
把整条链路连起来说一遍：
① 32 帧图像 → Encoder → 32 个 emb（每个 256 维）
② 从 t=0 开始循环：GRU 拿「上一帧的 z + 动作 + 本体」更新出 h[t]
③ h[t] 和 emb[t] 一起进 posterior，得到 z[t]
④ (h[t], z[t]) 去预测 emb（目标就是 emb[t] 本身）
⑤ z[t] 传给下一帧，回到 ②

后posterior 到底是什么

一句话

posterior 是一个很小的网络，它输出的不是「一个答案」，而是一个分布—— 也就是「我猜是这个值」加上「我有多不确定」。

先解释名字：先验 / 后验

名字字面意思输入
先验 prior看这张图之前的判断只有记忆 h
后验 posterior看完这张图之后的判断记忆 h + 当前图像 emb

就这么简单：「后」= 看过数据之后。

它的结构（只有 2 层）

post_net = Linear(456 → 200) → ELU → Linear(200 → 64)

维度说明
输入456cat(h, emb) = 200 + 256
输出64拆成两半：mu(32) + logvar(32)

输出的两个东西

输出维度含义UE 类比
mu32最可能的判断目标最可能的位置
logvar → std32不确定度（越大越没把握）误差半径 / 置信范围
64 维是怎么分的：前 32 个是 mu，后 32 个是 logvar （代码 post.chunk(2, dim=-1) 把 64 平均切成两块）。
std 不在输出里 —— 它是由 std = exp(0.5 × logvar) 算出来的派生量，不占维度。
类比：描述一个高斯只需要「均值 + 方差」两个数，标准差是现算的，不用单独给。

采样公式（就两行）：

公式说明
std = exp(0.5 × logvar)把 logvar 变回标准差
z = mu + std × 随机噪声在 mu 附近按 std 掷骰子

手算一个小例子（2 维，脚本可验证）：

量值
mu[1.0, -0.5]
logvar[-2.0, 0.0]
std[0.3679, 1.0]
随机噪声[0.5, -1.2]
z[1.1839, -1.7]　（1.0 + 0.3679×0.5 ；−0.5 + 1.0×(−1.2)）

为什么输出「分布」，而不是直接给个数

因为同一张画面可能对应多种真实状态。比如方块被挡住一半—— 它的确切位置是不确定的。用分布，模型就能表达「我没把握」。

同样的 mu，std 越大 → 采样结果越分散 = 越不确定

std 的作用：实测（mu 固定为 0，只改 std，各采样 6 次）

logvarstd6 次采样结果含义
−4.00.135[0.05, 0.02, 0.03, 0.03, −0.15, −0.03]几乎确定（都挤在 0 附近）
0.01.000[2.21, −0.64, 0.46, 0.27, 0.53, 0.81]中等
+2.02.718[3.02, −4.59, −2.69, 2.6, 3.59, 2.22]很不确定（散得很开）
理想情况：画面清楚时 std 应该小（很确定方块在哪）； 被遮挡时 std 应该大（没把握，只能给个大概范围）。
（当前是未训练模型，std 还是随机的；训练后它才会真正学会表达不确定性）

小细节：为什么输出 logvar 而不是 std

std 必须大于 0，如果让网络直接输出 std，就得额外加约束，不好优化。
改成输出 logvar：它可以是任意实数（正负都行）， 再 exp 一下自然变回正数 —— 数值稳定得多。

32 维里每一维都有自己独立的 mu 和 std。实测范围：
mu ∈ [-0.61, 0.31]，std ∈ [0.84, 1.31]（未训练）。

自己跑：python prism/docs/demo_04c_posterior.py

严格时序：h 不是被用两次，是「接力」

你可能注意到：GRU 用 h，posterior 也用 h —— 是不是同一份记忆用了两次？
不是。它们用的是不同时刻的 h：

步骤消费什么产出什么
① GRUh[t−1]（上一帧的记忆）+ z[t−1] + 动作 + 本体h[t]（新记忆）
② posteriorh[t]（刚算出来的）+ emb[t]z[t]
③ 预测头h[t] + z[t]emb_pred / 本体预测
是接力：GRU 先更新记忆，posterior 再消费这个新记忆 —— 消费的不是 GRU 输入的那份旧的。

不过你的直觉有一半是对的：h[t] 产出后确实同时被多个下游消费 （prior_net、post_net、obs_pred、proprio_pred 四个）。
这叫扇出（fan-out）——一次产出、多个消费者，不是"被用了两次"。

时间对齐表：谁产出、谁消费、和谁配对

时刻谁产出谁消费对齐关系
t−1GRU 产出 h[t−1]——
tGRU 消费 h[t−1] + z[t−1]→ 产出 h[t]h[t] 用的是上一帧的 z
t—posterior 消费 h[t] + emb[t]这俩是同一帧 ✓ → 产出 z[t]
t+1GRU 消费 h[t] + z[t]→ 产出 h[t+1]—
一句话记住：接力链是 z[t−1] → GRU → h[t]，然后 h[t] + emb[t] → posterior → z[t]。
记忆总是比图像"慢半拍"产出、但和当前图像同帧配对—— 这正是"用过去的经验理解现在看到的画面"。

zz 出来之后去哪

一句话

z（32 维）出来后兵分三路：一路往「未来」走，两路往「当前预测」走。

先把维度账记全（接着上一节）

步骤维度
cat(h, emb)456
post_net 输出64
拆开mu 32 ＋ logvar 32
算出 std32
采样得到 z32

三条路

路去哪维度结果
①传给下一帧的 GRU（和动作、本体一起）32+4+10 = 46更新出下一帧的 h
②和 h 拼起来进 obs_pred200+32 = 232 → 256猜出 emb_pred
③和 h 拼起来进 proprio_pred232 → 10猜出本体状态
z 往右上走「未来」，往右走「当前预测」

每条路的尽头都是一个 loss

猜出来的东西和谁比对应哪项 loss
emb_pred（256）真实的 emb（256）emb 预测 loss
emb_pred → Decoder → 图（3,64,64）真实图像重建 loss
proprio_pred（10）真实本体（10）本体 loss
（posterior 与 prior 两个分布的差异）—KL loss
接下来把三条路一条一条走一遍 —— 先走第①条（GRU）。

从这里回头看整条链

图像 → Encoder → emb(256) →（+h）posterior → z(32) →（+h）obs_pred → emb_pred(256) → ① 和 emb 比 ② 进 Decoder 还原成图
同时 z 传给下一帧 GRU → 继续循环

路①路①：z 往「未来」走 —— 交给 GRU

三条路一条一条讲。先走第①条：z[t] 传给下一帧，喂给下一帧的 GRU，更新出下一帧的记忆 h。 这条路是"记忆"的生命线。

下一帧的 GRU 吃什么

输入维度说明
z（上一帧的判断）32上一帧留下的信息
actions[t]4这一帧做了什么动作
proprio[t]10机械臂自身状态（位置、速度…）
合计46没有图像
这是整个设计里最重要的一个决定。
如果 GRU 直接吃图像，那么一旦没有图像（做梦/想象时）它就跑不动了。
现在它只吃「上一帧的判断 + 动作 + 本体」，所以完全可以在没有图像的情况下一直往前推。

等一下：46 维和 200 维，怎么放在一起运算？

你大概会卡在这里：输入 x 是 46 维，旧记忆 h 是 200 维， 维度都不一样，怎么相加？

答案是：各自乘一个矩阵，都投影成 200 维，然后相加。 不是把两个向量直接拼一起，也不是直接加。
x 经 (200×46) 矩阵、h 经 (200×200) 矩阵，都变成 200 维后才能相加

以「更新门 z」为例，公式就是：

项形状作用
x（输入）46z + 动作 + 本体
W_iz200 × 46把 46 维投影到 200 维
h（旧记忆）200上一帧的记忆
W_hz200 × 200把 200 维再变换一次（提取该用的部分）
相加结果200维度一致 → 可以相加

这 6 个 W 都是什么？

命名规则：下标第一个字母表示作用在谁身上，第二个字母表示属于哪个门。

矩阵形状读作
W_ir200 × 46input → r　输入 到 重置门
W_iz200 × 46input → z　输入 到 更新门
W_in200 × 46input → n　输入 到 候选
W_hr200 × 200hidden → r　记忆 到 重置门
W_hz200 × 200hidden → z　记忆 到 更新门
W_hn200 × 200hidden → n　记忆 到 候选

规律：W_i? 都吃输入 x（列数 46）；W_h? 都吃记忆 h（列数 200）。

它们在代码里怎么存

PyTorch 不存 6 个矩阵，而是三个一组竖着堆起来：

参数形状切片对应
weight_ih(600, 46)[0:200]W_ir
[200:400]W_iz
[400:600]W_in
weight_hh(600, 200)[0:200]W_hr
[200:400]W_hz
[400:600]W_hn

上面那个手算小例子就是按这个切片取权重算的，结果与程序输出一致 —— 规则已被验证。

顺带纠正一个说法：是「两个门 + 一个候选」

输出范围本质UE 类比
r 重置门0 ~ 1阀门：算新候选时，旧记忆参与多少音量旋钮
z 更新门0 ~ 1阀门：最终混合时，旧记忆保留多少音量旋钮
n 候选−1 ~ 1不是门，是要写入的新内容要写进黑板的内容

判断标准：过 sigmoid、输出 0~1 的才是「门」（像阀门控制流量）； n 过 tanh、输出 −1~1，是内容本身。
所以准确说法是：GRU 有 2 个门，加上 1 个候选记忆 —— 一共 3 组权重。

三个量都是这么算出来的

量公式激活
rW_ir·x + W_hr·hsigmoid
zW_iz·x + W_hz·hsigmoid
nW_in·x + r⊙(W_hn·h)tanh
h'(1−z)⊙n + z⊙h—
注意 n 的公式里有个 r⊙(...)： 重置门 r 控制旧记忆对"新候选"的贡献 —— r≈0 表示"算新东西时别管旧记忆"，r≈1 表示"把旧记忆全用上"。

三个分支的关系：可以理解成 3 个独立的线性层

易错点 h' = (1−z)⊙n + z⊙h 里只有 z 和 n，看不到 r —— r 去哪了？

你的直觉完全正确：3 个独立的小分支，对同一份 x 和 h 各算各的。

分支吃什么输出结果拿去干嘛
r 分支x, hr (200, 0~1)去参与 n 的计算
n 分支x, h，还有 rn (200, −1~1)新内容的候选值
z 分支x, hz (200, 0~1)去参与 h' 的混合
为什么 h' 的公式里看不到 r？
因为 r 在上游已经用掉了 —— 它参与了 n 的计算，r 的影响已经"烧进" n 里。
数据流：x, h → r → n → h' ← z
r 是内层门（管新内容怎么算），z 是外层门（管新旧怎么混）。 唯一的交叉点就是：n 的计算要用到 r，其余各分支互不相干。
这些 W 就是普通的线性层（Linear，y = W·x + b）： 148,800 个参数全部可学习，跟着 loss 被梯度下降更新。
一个符号约定要记清：PyTorch 写的是 h' = (1−z)⊙n + z⊙h，也就是 z 越大 = 越保留旧记忆。
这和前面 Lerp 图里的 alpha 正好相反：alpha = 1 − z。 （alpha=0 = 完全不更新 = z=1）

先补两个工具函数（不然下面会看不懂）

后面会反复用到两个"压缩函数"，先认识它们。

① sigmoid：　σ(x) = 1 / (1 + e^(−x))

作用：把任意实数压到 0 ~ 1 之间。

输入01−12−210−10
输出0.50000.73110.26890.88080.11921.00000.0000
为什么需要它：因为"门"要输出的是比例，比例必须在 0~1 之间。
sigmoid 就是干这个的 —— 不管输入是 −100 还是 +100，输出一定落在 0~1， 输入 0 时正好是 0.5（一半一半）。

② tanh：把任意实数压到 −1 ~ 1 之间。

输入01−12−2
输出0.00000.7616−0.76160.9640−0.9640
分工：sigmoid 用于比例 / 门（必须 0~1）； tanh 用于内容（可正可负）。

为什么需要两个门？一个不行吗

一个门也能跑（最朴素的 RNN 连门都没有）。GRU 用两个是分工：

门管什么
r 重置门算「新候选 n」时，旧记忆掺进去多少
z 更新门最终混合时，旧记忆保留多少
分开的意义：模型能做到「用旧记忆算出新内容（r 大），但最后决定不采纳（z 小）」。 一个门做不出这种组合 —— 这就是 GRU 比朴素 RNN 强的地方。

最后得出什么

一个 200 维的新向量 h' —— 这一帧的新记忆。
它接下来做两件事：
① 传给下一帧的 GRU，继续算（回到步骤 1）
② 和 z 拼成 232 维，去喂 obs_pred / proprio_pred

门：alpha 是网络算出来的

前面公式里的 z 和 r 就是控制更新幅度的门： 每一维各自一个 0~1 的数（sigmoid 保证的），由网络根据当前输入算出来，不是常量。
200 维里每维一个独立的门 —— 所以它能同时做到"记住方块位置"和"忘掉桌面纹理"。

为什么需要门？不能直接累加吗

朴素写法 h = h + x 累加 6 步后（脚本实测）：[3.0, 3.0, 3.0, 3.0]

只会越滚越大 —— 该忘的忘不掉，数值还会爆炸。 门的作用就是让模型学会什么时候该忘、什么时候该记。

路②③路②③：z 往「当前预测」走

先重新把总览图摆出来 —— ①已经在上一节走完，现在走②③：

①（左上）上一节讲完了；②③走的是中间这条「cat(h,z) → 232」的路

路②和路③是同一类操作

两条路的输入完全相同：把 h（200）和 z（32）拼成 232 维，各自过一个线性层。

路线性层输出含义
②obs_pred（232 → 256）emb_pred模型猜的当前帧画面摘要
③proprio_pred（232 → 10）本体预测模型猜的机械臂自身状态

路②的产物有两条出路

出路和谁比对应 loss
直接和真实的 emb[t]（256）比Encoder 算出的真实摘要emb loss
送进 Decoder 还原成图（3,64,64）真实的输入图像重建 loss

路③的产物只有一条出路

出路和谁比对应 loss
和真实的 proprio[t]（10）比数据里记录的本体状态本体 loss
三条路到此全部走完：①喂给下一帧 GRU（时间上延续）， ②③猜当前帧的摘要和本体（每一帧的预测）， 每条路的尽头都是一个 loss —— 四项加起来就是下一小点的内容。
一个容易疑惑的点：为什么 obs_pred 猜的是「当前帧」而不是「下一帧」？
因为训练时 z 来自 posterior（看过当前帧图像），所以它是在做「重建练习」——目的是练出好的 h 和 Decoder。
真正的「预测未来」发生在想象模式：z 改从 prior 来（不看图），同样的网络就能一步步往前推 —— 就是「两种运行模式」那节讲的内容。

同一个模块，两种用法

模式z 来源obs_pred 在做什么准确叫法
训练（有图）posterior看着画面 → 压成摘要 → 再还原回来重建（练表征）
想象（无图）prior凭记忆猜这一帧长什么样想象 / 预测
所以「学会想象」这件事：模块是同一个（obs_pred），但要配合 prior 才是想象。
训练阶段它练的是「理解当前画面」，练出来的 h 和 Decoder，才是想象时能拿来用的东西。

为什么还要单独有个「路③」

本体状态（10 维）是低维、精确、和动作强相关的信号。单独给它一个监督，有两个作用：

  • 给训练一个稳定的辅助信号——像素重建噪声大，本体预测收敛快，能带着 h 先学好
  • MPC 做决策时需要知道「机械臂自己会到哪」，这个预测直接可用

源z 的两个来源：prior 与 posterior

z 有两个来源，这是 RSSM 的精髓：

路径输入含义什么时候用
prior p(z_t | h_t)只有 ht凭记忆猜：不看当前画面，只靠记忆推断世界现在什么样想象 / 做梦时（没有图像）
posterior q(z_t | h_t, emb_t)ht + 当前图像看到真相后修正：记忆的猜测 + 当前这一帧的真实信息训练时（有图像）
UE / 工程类比：这就是卡尔曼滤波
  • prior = predict 步：根据上一状态预测现在
  • posterior = update 步：拿到观测后修正预测
RSSM 就是把卡尔曼滤波的两步用神经网络实现，并让它自己学该记什么、该信观测多少。
KL 项的完整解释（公式 + 为什么它决定"想象力"）已移到 笔记 05 · loss 四项。这里只记一句：
KL(q ‖ p) = 逼 prior（凭记忆猜）去模仿 posterior（看过图后的判断）。

结构上唯一的差别：谁看了图像

输入维度网络
prior只有 h200Linear(200→200) → ELU → Linear(200→64)
posteriorcat(h, emb)456Linear(456→200) → ELU → Linear(200→64)

就差一个 emb（当前帧图像）。其余结构一模一样，输出也都是 mu(32) + logvar(32)。

训练时：两条都算，但只用 posterior 采样

这是最容易搞错的地方。看代码：

步骤代码说明
①prior = self.prior_net(h)先算出 prior（凭记忆）
②post = self.post_net(cat([h, emb[t]]))再算出 posterior（看了图）
③z = self._rsample(mu_q, lv_q)只用 posterior 采样 —— 拿去预测、重建
④kl = 0.5*(lv_p - lv_q + ...)prior 不参与预测，只用来算 KL
所以训练时 prior 是陪练：它自己不产出 z， 唯一的作用是提供 KL 这一项损失，让"凭记忆猜"的能力被练出来。

为什么要分开：开卷考试 vs 闭卷考试

训练时两条路都跑；想象时只剩 prior 这条路
posterior = 开卷考试（能看当前画面）→ 答案准
prior = 闭卷考试（只凭记忆）→ 一开始答得很差
KL = 逼闭卷成绩去追开卷成绩

结果：模型被迫把画面里的关键信息写进记忆 h—— 因为只有记住了，闭卷才答得出来。这就是"想象力"的来源。

它们怎么协作：一个完整时间线

阶段prior 在干嘛posterior 在干嘛
训练（有图）算出来，但只贡献 KL产出 z，用于预测和重建
想象（无图）产出 z，一路往前推用不了（没有 emb）
遮挡（图不可靠）仍然可靠（不看图）被污染（看图但图是坏的）

实测：遮住画面后，谁靠不住了

把当前帧换成全黑，对比两者的输出变化：

输出变化结论
posterior0.0012被污染了（它依赖图像）
prior0.0000纹丝不动（结构决定它不看图）
这解释了整个设计的动机：没有图像时，prior 是唯一能用的那条路。 如果只训 posterior，模型一遇到遮挡就废了。

结三个记忆点

  • 一帧 → Encoder → emb(256) →（+h）posterior → z(32) → 三条路
  • GRU 不吃图像（输入 = z + 动作 + 本体 = 46 维）——这是"能做梦"的结构原因
  • prior = 凭记忆猜，posterior = 看了图修正；两者靠 KL 协作（公式见笔记 05）
  • 三条路的尽头都是 loss —— 四项 loss 见笔记 05
