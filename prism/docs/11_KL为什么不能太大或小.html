KL 为什么不能太大 / 太小

PRISM-WM 笔记 11 · 用 observe → imagine 全流程讲清 KL 的"适中"要求

一句话：KL 衡量 z 装载了多少来自当前画面的信息。 装太少 → z 是空壳，想象发散；装太多 → prior 学不会，想象也不准。必须适中。

KL 太小KL 适中 ✅KL 太大

prior 学不会
z 的状态空壳（只反映记忆）装了可预测的有用信息装满但多为不可预测的细节
想象后果发散（末端飞出场景）准不准（prior 给不出对的 z）
我们的数据0.006 → 110cm ❌—KL 占 loss 95%（量级失衡）

1前置：z 是画面信息进入预测的唯一入口

120  hz = torch.cat([h, z], dim=-1)              # (B, 232)
121  emb_pred = self.obs_pred(hz)                # 预测画面摘要 —— 只吃 (h,z)
122  proprio_pred = self.proprio_pred(hz)        # 预测本体
注意：obs_pred 吃不到 emb。图像信息只能通过 z 进入预测通路，所以 z 必须装载画面信息，否则模型只能"照记忆猜"。

2贯穿图：observe → (h,z) → imagine

observe：h 滞后一帧、z 含最新画面；imagine：z 只来自 prior，且用自己上一步的预测当输入（正反馈）

3KL 太小：模型学会"照记忆搬"

我的理解（原话）：KL 太小，导致 observe 产出的 z 和记忆太过于相近，偏离真实图像； 模型学到"只要不看图、照着记忆搬，我的 KL loss 就很小"，于是 post 网络直接输出接近记忆的结果，导致失真。 这是训练的问题。imagine 时这个贴近记忆的结果又进入 prior 推理，结果就是一直偏离现实。

代码里的机制

147  gru_in = torch.cat([z, actions[t], proprio[t]])   # z 是上一帧的 → h 滞后一帧
148  h = self.gru(gru_in, h)
149  post = self.post_net(torch.cat([h, emb[t]], -1))   # posterior 本该用上 emb（画面）
151  z = self._rsample(mu_q, lv_q)                      # 但输出却 ≈ prior（没用画面）

为什么训练会导向这里（两个 loss 合谋）

loss 项给了什么压力
recon数据近乎静态 → 只靠 h 的惯性也能重建 → 不需要 z
KL奖励 posterior 靠近 prior → 奖励"少装信息"
两者方向一致 → 梯度指向"让 z 躺平" → 模型真的躺平了。 这不是代码 bug，是 数据 + 训练目标 共同导致的。

实测后果（不是"保持偏离"，是滚雪球）

偏离是放大的，不是恒定的：每步拿自己上一步的错误当输入 → 0.9cm → 110cm。

4KL 太大：为什么也不行

KL 太大 = posterior 装了大量 prior 预测不了的信息。三个后果：

后果说明
① 想象失效训练用 posterior、想象用 prior。两者差太远 → 想象时 prior 给出的 z 落在训练没见过的区域 → decoder 输出乱
② 装了无用的细节z 会去记住"当前帧特有的、无法从历史预测的东西"（随机纹理、未建模噪声）→ 对推演未来没用，反而干扰
③ 量级失衡KL 项主导 loss → 其他项（recon/emb/proprio）的梯度被淹没
③ 我们正好有实测：KL 占总 loss 的 95%+（recon 0.0006、KL 0.02~0.1，差 30~100 倍）。 所以"看总 loss 判断训练"没意义——它基本就是 KL。

一个关键不对称（为什么塌缩更容易发生）

loss 对"太大"有天然惩罚（KL 项要最小化），但对"太小"是天然鼓励的—— 所以 z 塌缩是"顺着梯度走"的，必须靠额外机制阻止。

这个机制就是 free_bits（rssm.py 199–201 行）：给 KL 设下限，不许它低于这个值。

199  if free_bits > 0:
200      kl = torch.clamp(kl, min=free_bits)   # 低于地板 → 顶到地板（此段梯度变 0）

5易混：绝对值小 ≠ 相对占比小

维度我们的值问题
绝对值（信息量）0.005 ~ 0.020 nat❌ 太小 → z 空壳、想象发散
相对占比（占 loss）95%+❌ 太大 → 其他项梯度被淹没
这两件事同时成立且不矛盾：z 自己几乎没装东西（绝对值小）， 但因为其他三项都小到 1e-4 量级，KL 反而成了 loss 的绝对主力。

6警戒线与现状

指标警戒线我们的现状
真实 KL（绝对值）< 0.001 = 塌缩；< 0.01 = 发散风险0.005 ~ 0.020 ⚠️
想象位置误差应 < 静止基线（约 8cm）21cm（v2）/ 110cm（0.01）❌
结论：调 free_bits 只能在"塌"和"不塌"之间选，救不了动力学。 真正缺的是给 (h,z) 加位置监督（v5 物体位置预测头），让 z 被迫装载真实的画面信息。
