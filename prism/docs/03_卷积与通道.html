0先澄清：括号里的数字是什么

同一个东西有两种写法，很容易搞混：

场合排列例子通道位置
磁盘 / numpy(H, W, C)(64, 64, 3)最后
PyTorch 张量(C, H, W)(3, 64, 64)最前
所以本文里的 (32, 32, 32) 读作 （通道 32，高 32，宽 32）， 最后一个 32 不是通道。PyTorch 实际是 4 维 (B, C, H, W)，笔记里省略了 batch 维 B。

1卷积 = 一个小窗口在图上滑

为了能手算，用一张 4×4 的图和一个 2×2 的窗口 （注意：2×2 只是教学例子，真实网络用的是 4×4 的 kernel，见第 3 节）。 窗口从左上角开始，每次右移一格，到行尾换下一行。

输入 4×4（黄色 = 当前窗口）
→
输出 3×3（逐个填出来）
点「下一步」开始：窗口盖住 4 个数 → 加权求和 → 填进输出格
窗口每次移 1 格 = stride=1。2×2 的窗在 4×4 的图上只能停 3×3 = 9 个位置，所以输出是 3×3
这个演示是 stride=1。真实 Encoder 用 stride=2：窗口每次跳 2 格，画面直接减半。 同一张 4×4 图，stride=2 时窗口只有 4 个位置（正好互不重叠铺满全图），输出变成 2×2：
stride=2 的 4 个输出值，正好是 stride=1 那个 3×3 输出的四个角（6, −7, 7, −8）——跳着采样
stride输出尺寸公式4×4 图 + 2×2 kernel真实第一层 (64, k4, p1)
1(n−k)/1 + 1(4−2)/1+1 = 3—
2(n−k)/2 + 1(4−2)/2+1 = 2(64−4+2)/2+1 = 32
三个要点
  • 权重共享：kernel 只有 4 个参数，却产出了 9 个数 —— 同一组权重全图复用
  • 只看局部：每个输出只关心 2×2，不是整张图
  • 权重是学出来的：上面那个"找竖边"的核是为了好懂手写的，训练时会自己变成有用的样子

2kernel 不是 2D，是 3D

真实第一层 kernel 的形状是 (3, 4, 4) —— 窗口是 4×4（不是演示里的 2×2）， 共 3 层压在 R / G / B 上。三层各自算完，加在一起得到 1 个数。

三个通道 × 各自的 kernel 层 → 三个数 → 相加 → 1 个数
这就是"为什么输出不是 3 通道"的答案： 一个 kernel 把所有输入通道汇总成一个数，所以它只产出 1 个通道。

3通道数 = kernel 的个数

想要多少输出通道，就用多少个不同的 kernel。这是我们自己定的，与输入通道数无关。

kernel 个数 N每个 kernel 形状输入输出参数量
1(3,4,4)(3,64,64)(1,32,32)48
3(3,4,4)(3,64,64)(3,32,32)144
32(3,4,4)(3,64,64)(32,32,32)1536
256(3,4,4)(3,64,64)(256,32,32)12288
kernel 尺寸固定 4×4（形状 (3,4,4)），变的只是个数；输出 64→32 是因为 stride=2, padding=1

4完整旅程：画面变小，通道变多

Encoder 的 4 层卷积就是这个规律。每层 stride=2 让画面减半，通道数则由我们递增。

位置越来越少（64→4），每个位置携带的信息越来越多（3→256）

每层的 kernel 形状都不一样

kernel 形状的规律：(输出通道数, 输入通道数, 4, 4) = （kernel 个数，每个 kernel 的层数，窗口）。 窗口永远是 4×4，但层数跟着输入通道变，个数跟着输出通道变：

层kernel 形状解读
Conv(3→32)(32, 3, 4, 4)32 个 kernel，每个 3 层（压在 RGB 上）
Conv(32→64)(64, 32, 4, 4)64 个 kernel，每个 32 层（压在上层的 32 通道上）
Conv(64→128)(128, 64, 4, 4)128 个 kernel，每个 64 层
Conv(128→256)(256, 128, 4, 4)256 个 kernel，每个 128 层
所以"每层都是 (3,4,4)"是不对的——只有第一层是 (3,4,4)。 之后每层 kernel 的层数等于上一层的输出通道数。 这正呼应第 2 节：kernel 层数 = 输入通道数，而输入通道在逐层膨胀。
为什么不能一直保持 3 通道？
画面缩小到 4×4 时，若只有 3 通道，就只剩 3×4×4 = 48 个数，信息全丢了。 信息只能往通道数里装，所以必须 3 → 32 → 64 → 128 → 256。

5一个坑：padding

写验证脚本时第一次漏了 padding，输出变成 31 而不是 32：

设置公式输出尺寸
padding=1（真实写法）(64 − 4 + 2) / 2 + 132 ✓
padding=0(64 − 4) / 2 + 131 ✗
ObsEncoder 用 padding=1，让尺寸正好减半（64→32→16→8→4）。

每个 kernel = 一个通道生成器：读全部输入通道，产出 1 个新通道 （比如"这里有没有橙色方块的边缘"）。32 个 kernel = 跑 32 个滤镜 → 32 通道的 buffer。

7三个记忆点

  • kernel 是 3D 的：形状 (输入通道, k, k)，一个 kernel 把所有输入通道汇总成 1 个数
  • 输出通道数 = kernel 个数，想设多少设多少，与输入通道数无关
  • 排列顺序：numpy 是 (H,W,C)，PyTorch 是 (C,H,W)
